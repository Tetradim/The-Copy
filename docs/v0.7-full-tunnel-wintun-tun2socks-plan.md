# v0.7+ Full Tunnel plan: Wintun + tun2socks

This is a planning document only. v0.6.1 does not create adapters, change routes, change DNS, or install drivers.

## Target architecture

```text
Windows apps
  -> Windows TCP/IP stack
  -> Wintun virtual adapter
  -> tun2socks/gVisor-style userspace stack
  -> local TetherBridge SOCKS5 relay
  -> Android bridge service
  -> phone internet
```

## Why this is deferred

Proxy mode is safe to ship first because it only snapshots/restores the current user's WinINet proxy state. Full Tunnel mode touches machine-wide networking and requires admin/elevated operations. It needs a separate service and much stronger restore logic.

## Required pieces before enabling

1. **SOCKS5 endpoint**
   - Current v0.6.1 relay is HTTP/HTTPS proxy oriented.
   - tun2socks should point at a SOCKS5 endpoint, so v0.7 must add a real local SOCKS5 listener or Android SOCKS5 bridge.
   - TCP CONNECT equivalent is the minimum; UDP ASSOCIATE is needed for QUIC, DNS, games, and many non-browser apps.

2. **Elevated Windows service**
   - Creates/deletes Wintun adapter.
   - Assigns tunnel interface IP.
   - Snapshots and restores routes, DNS, interface metrics, and proxy state.
   - Owns crash recovery.

3. **Route/DNS policy**
   - Add a host route that keeps the phone bridge reachable outside the tunnel.
   - Route default traffic to the tunnel adapter.
   - Set DNS deliberately or run a local DNS proxy.
   - Decide IPv6 policy before shipping.

4. **tun2socks integration**
   - Either launch a vetted tun2socks binary as a supervised subprocess or embed equivalent functionality.
   - Bind/protect the tun2socks outbound path so it does not route back into itself.
   - Surface logs and counters in the same Windows Traffic/Logs tabs added in v0.6.1.

5. **Safety and rollback**
   - Full snapshot before any adapter/route/DNS change.
   - Idempotent restore on normal disconnect, app crash, service restart, or Windows resume.
   - Clear UI warning that Full Tunnel is admin/elevated and more invasive than Proxy Bridge.

## v0.7 skeleton status

The source contains only planning stubs. No code in v0.6.1 calls Wintun, launches tun2socks, or changes routes/DNS.
