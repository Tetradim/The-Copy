# v0.7 Wintun + tun2socks implementation plan

This file records the full-tunnel investigation without enabling full-tunnel UI in v0.6.1.

## Decision

Use Wintun as the Windows Layer-3 adapter and a tun2socks/gVisor-style engine to translate packets into proxy traffic. Keep this behind an elevated service.

## Project layout target

```text
windows/
  TetherBridge.Desktop/           # unelevated UI
  TetherBridge.FullTunnelService/ # elevated service, v0.7+
    Adapter/                      # Wintun loading/PInvoke or wrapper
    Routing/                      # route/DNS snapshots and restore
    Engine/                       # tun2socks process supervision
    Control/                      # named-pipe API from UI
```

## Service API draft

```text
StartFullTunnel(phoneTransport, socksEndpoint, dnsPolicy, ipv6Policy)
StopFullTunnel(reason)
GetFullTunnelStatus()
RepairNetworkState()
ExportFullTunnelDiagnostics()
```

## Safety requirements

- Service must refuse to start unless a clean proxy-mode phone session is already healthy.
- Service must create a route exception for the phone connection before changing the default route.
- Every route/DNS/proxy change must have a persisted restore record.
- Crash recovery must run on service startup before accepting a new full-tunnel session.
- Full tunnel must have a clear UI warning that admin privileges and networking changes are required.

## Open work before implementation

- Add a real SOCKS5 endpoint to the local relay/Android bridge.
- Choose whether to bundle tun2socks binary or build a small managed supervisor around it.
- Choose DNS policy and IPv6 policy.
- Create integration tests on a real Windows machine with a real Android phone.
