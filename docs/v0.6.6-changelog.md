# TetherBridge Windows 0.6.6 / Android 0.6.5 test builds

- The local SOCKS5 relay supports UDP ASSOCIATE for explicitly configured clients. UDP datagrams travel through authenticated phone-side tunnels over framed USB or pinned TLS. DNS queries can use this proxy path, but system-wide DNS is not configured by the app.
- Android reports its UDP capability. Windows falls back to TCP-only SOCKS and explicitly rejects UDP if paired with an older Android build.
- Android uses separate internal USB and Wi-Fi/PAN ports so changing modes does not fail because a recently used TLS listener still occupies the other mode's port.
- Stopping the Android bridge closes its active client connections, including UDP tunnels.
- Tests on the Samsung Android 16 tablet covered UDP echo for empty, small, and 40000-byte packets; DNS responses; HTTPS and TCP half-close over framed USB; and encrypted UDP/HTTPS through a temporary ADB forward. The physical Wi-Fi/PAN path and the OnePlus have not been tested.
- Full-computer routing, Wintun/route management, crash-safe network restoration, Wi-Fi Direct, and a Bluetooth socket tunnel remain unimplemented. UDP fragments and datagrams over the protocol limits are rejected.
