# v0.6 merge notes

This release is a cleanup merge after reviewing two independent v0.4 hardening attempts. It keeps the parts that were actually more correct and removes UI that could mislead testers into thinking unfinished transports were live.

## Adopted

- Windows header/body boundary preservation remains in place through `HeaderReadResult` and `Tail`.
- Android header/body boundary preservation remains in place through `HeaderReadResult(header, tail)` and explicit forwarding of `tail` before pump handoff.
- Android `forwardHttp` pumps from the same `InputStream` passed through the header parser; no fresh raw socket stream is used after buffered/tail reads.
- Android authentication backoff is per peer and implemented with `ConcurrentHashMap<String, AtomicInteger>`, avoiding a global synchronized sleep.
- Android overload uses an explicit `RejectedExecutionException` catch so one queue overflow closes only the rejected client connection.
- Wi-Fi Direct and Bluetooth socket transports remain documented parity targets, not active buttons.

## Deliberately not exposed as active UI

The Android app does not show `Wi-Fi Direct Bridge Target` or `Bluetooth Socket Target` buttons until real Wi-Fi P2P group management and real RFCOMM transport code exist. Plain Wi-Fi Bridge and Bluetooth/PAN Assist remain available because they have actual behavior behind them.

## Still not a finished original-like replacement

The project still lacks:

- Real Wi-Fi Direct group creation/discovery.
- Real Bluetooth RFCOMM data transport.
- Rich traffic viewer beyond basic counters.
- Full-laptop routing through a Windows virtual adapter.

Those belong in a feature-parity sprint, not in a hardening merge.
