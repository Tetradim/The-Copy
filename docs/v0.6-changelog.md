# v0.6 changelog

v0.6 is a merge/correctness release. It keeps the v0.5 transport boundary and applies the review feedback that should be adopted before adding speculative parity features.

## Fixed / improved

- Moved Android failed-auth backoff into `AuthFailureBackoff.kt`.
- Uses `ConcurrentHashMap<String, AtomicInteger>` for per-peer failure counters.
- Sleeps outside any synchronized/global monitor so one bad peer cannot stall unrelated connections.
- Adds explicit `ThreadPoolExecutor.AbortPolicy()` and catches `RejectedExecutionException` around each accepted client.
- Overload now sheds the one rejected client instead of risking accept-loop shutdown.
- Keeps the Android request-body preservation path intact: `readHeader()` returns `HeaderReadResult(header, tail)`, `forwardHttp()` writes the tail, and `pipeBoth()` continues from the same `clientInput` stream.
- Adds regression markers for the exact Android body-preservation wiring bug called out in review.
- Keeps Wi-Fi Direct and custom Bluetooth Socket transport out of the active UI until real transports exist.
- Adds a small Android UI note that only USB Bridge, Wi-Fi Bridge, and Bluetooth/PAN Assist are active in this build.

## Still not implemented

- Real Wi-Fi Direct/P2P group creation.
- Real Bluetooth RFCOMM data tunnel.
- Full laptop routing via virtual adapter.
- Binary build validation in this environment.
